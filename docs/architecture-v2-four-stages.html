四段式干净版 · 一个综合 agent + 一条死规则尾巴

把上一版 18 个平铺节点收敛成 4 段。能力没丢，只是重新组织：理解交给一个综合 agent，钱和契约交给一条薄薄的死规则尾巴。

原则：综合 agent 负责「理解和提议」，死规则尾巴负责「把关和落账」。agent 可以大胆推理，但幻觉记不进账。

主流程 · 四段

1

读进来 · 文件变原文

死规则 + 解析补救 agent
输入文件→按后缀路由→解析成 RawDocument
软失败（文字够不够干净/结构化）→解析补救 agent⇄换路重解析（文本层空→OCR / 某页糊→重OCR那页），≤2 次
硬失败且救不回 →PENDING_REVIEW（绝不拿垃圾往下跑）
↓
2

双路抽取 · 各出一份草稿

规则 + LLM
RawDocument→规则正则抽取草稿一
RawDocument→LLM 结构化抽取草稿二（可选，无 key 降级）

两路都只"读"，不做最终决策；结果一起交给第 3 段。

↓
3

综合 agent · 唯一的"脑子"

理解 + 提议，带工具
草稿一+草稿二+原件+台账→综合 agent
它自己核对相同/不同、必要时调原文，产出完整提案：
reconciled 字段归一化费用名匹配老账单AR/AP 推理
工具：读原文查台账查费用名字典

它只产"提案 + 理由"，不直接落账；理由写进 audit_trail。

↓
4

死规则尾巴 · 把关和落账

薄 · 全死规则
校验→定 operation→落账 + 六字段 JSON→输出
任何不可信 →PENDING_REVIEW

校验=挑数字毛病；定 operation=CREATE/UPDATE/NO_CHANGE/PENDING_REVIEW；落账=角色→AR/AP 那一下死规则 + 按契约写 JSON。

软失败的边界（第 1 段闸门）

一句话：读出的文字，够不够干净、够不够结构化，能让我试着抽字段？ 可判定指标：

  • 有没有金额样子的数字；有没有至少一条费用行；
  • 有没有任何单号/箱号；OCR 置信度是否太低；
  • 金额里是否混了字母、日期是否可能。

够 → 进第 2 段；不够 → 软失败 → 补救 agent 换路；救不回 → PENDING_REVIEW，不跑下游。

综合 agent · 模块视角

它拿到什么两份结构化草稿 + RawDocument 原件 + 台账访问 + 记账主体配置。
东西从哪来第 2 段两路抽取；原件来自第 1 段；台账是运行时输入。
它干什么核对两稿异同、必要时读原文；归一化费用名；认亲匹配老账单；推理 AR/AP 角色。产出一份完整提案 + 理由。
它交回什么提案（reconciled 字段 / 标准名 / 匹配结果 / 角色候选）+ 置信度 + 理由，交给第 4 段。
它拿不到什么不直接写台账、不直接落账、不改输出契约；拿不准就标低置信，交尾巴转人工。

死规则尾巴 · 三步大白话

校验

挑数字毛病：金额是数字吗、币种是真实 ISO 码吗、明细加总=合计吗、箱号校验位对吗、有无 OCR 混淆。产 issues + 置信度。

定 operation

结合匹配+校验：没匹配到=CREATE；匹配到有更新=UPDATE；无变化=NO_CHANGE；有阻断/低置信=PENDING_REVIEW。

落账 + 输出

角色→AR/AP 那一下用死规则（同输入同结果、可测试）；按题目六字段契约写 JSON，扩展全进 audit_trail。

18 → 4 收敛对照（能力没丢，只是重组）

段收进来的旧节点性质
1 读进来A 输入 / B 路由 / C 解析 / H 补救 / P 兜底死规则 + 补救 agent
2 双路抽取D 规则 / E LLM死规则骨架里的 LLM
3 综合 agentG 融合 / I 归一化 / J+K 匹配 / L+N AR/AP 推理 / F 裁判(并入软失败闸门)一个 agent
4 死规则尾巴M 校验 / O 判定 / L 落账那一下 / Z 装配 / OUT 输出 / P 兜底薄死规则

注：AR/AP 的"推理"在第 3 段 agent，"角色→AR/AP 落账那一下"在第 4 段死规则——推理放 agent，落账放规则。

自主与安全的取舍

把匹配/归一化/AR/AP 推理收进一个 agent，自主性更强、节点更少，但 LLM 输出不如死规则可复现。对策：agent 只产提案，第 4 段死规则对钱关键项（金额、落账方向、operation）复核，匹配结果能用确定性键查表的就交叉验证。这样既自主，又不会把错账悄悄记进总账。

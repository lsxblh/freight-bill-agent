# 四段式 v2：综合 agent 为命脉，死规则尾巴把关落账

把 18 个平铺节点收敛为四段：读进来（软失败闸门 + 解析补救 agent）→ 双路抽取 → 综合 agent → 死规则尾巴。综合 agent 集中负责"理解与提议"（核对两稿、归一化、认亲匹配、AR/AP 推理），以 ReAct 工具循环（工作台）自主决定何时调用哪个工具；它是本项目的命脉，必须配 API key、无 key 不降级；第 2 段 LLM 草稿可选，读失败留空、不阻断流程；四级匹配做成确定性工具由 agent 调用，agent 只推理疑难 case；软失败闸门用"代码指标 + 小模型裁判"混合；钱与输出契约由死规则尾巴把关：落账前对钱关键项做确定性交叉验证（金额重算、匹配用认亲工具复查、方向用四要素规则复查，复用现有校验/匹配/过账代码），再结合校验 issues 与 agent 自标低置信，任何一项对不上或不可信即 PENDING_REVIEW。如此 autonomy 集中在一个 agent，又保证可复现、幻觉记不进账。本决定取代 11-07「确定性骨架 + 独立小模型质检 + 多个定点 agent」的旧架构决定。

## Considered Options

- 18 节点、多个定点 agent：被否，用户嫌碎、过于工作流，autonomy 分散。
- 综合 agent 全权负责所有匹配：被否，会把确定的四级匹配也变成不可复现。
- 无 key 退纯规则：被否，与"本项目就是需要 agent"的定位冲突。

## Consequences

- 测试必须给综合 agent 注入 / mock 假 LLM，不能无 key 裸跑；离线无 key 演示不再可用。
- "综合 agent 必须配 key"是行为变更，落在"搬骨架不改行为、89 测试全绿"之后的步骤，不在第一步。
- 四级匹配工具的返回是"事实"（认没认出、哪条、第几级），不是决策；决策由 agent 提议、尾巴落账。
